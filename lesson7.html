꼭 가스 센서를 쓸 필요는 없어요

LED만으로도 좋은 프로젝트가 됩니다. 입김 세기 게임, 반응 속도 테스트, 감정 표현 조명처럼요. MQ2가 내 아이디어에 안 맞으면 빼도 됩니다. 문제가 먼저고, 부품은 그다음입니다.

평가는 완성도가 아닙니다

이 수업에서 점수가 되는 건 매끈한 결과물이 아니라 과정입니다. 무엇을 만들려 했고, 어디서 막혔고, 어떻게 풀었고, 친구 의견을 어떻게 반영했는지. 그래서 기록이 곧 작품입니다.

Add file → Create new file로 LOG.md와 main.py를 만들어 둡니다. 지금은 비어 있어도 됩니다. 오늘 채워 나갈 거예요.

활동 2. 아이디어 모으기

목표 — 막막함을 이야기로 푼다

처음엔 다들 막막합니다. 지난 학기 학생도 그랬어요.

"처음에는 뭘 만들어야 할지 막막했다. 친구들이랑 이야기하면서 아이디어가 나왔다."

그래서 먼저 같이 이야기합니다. 정답을 찾는 게 아니라 많이 꺼내는 게 목적이에요. 아래는 지난 학기 학생들이 실제로 낸 것들입니다.

공기 상태 LED 게이지

가장 많이 나온 방향

공기가 좋으면 초록 한두 칸, 나빠지면 노랑으로 차오르고, 위험하면 빨갛게 깜빡. 5·6차시에 만든 것에서 바로 출발할 수 있습니다.

한 걸음 더 — 교실별·수업 전후로 값을 비교하거나, 폰 대시보드에 기록을 남기기

교내 화재·연기 감지 알람

환경 문제로 확장

연기가 감지되면 LED가 빨갛게 번지며 경보. MQ2가 연기에 반응하는 성질을 그대로 씁니다.

생각할 점 — MQ2는 연기와 다른 가스를 구분하지 못합니다. "진짜 불"만 잡아낼 수 있을까요? 이 한계를 발표에 담으면 좋은 재료가 됩니다

흡연 감지 시스템

문제 상황이 뚜렷

화장실이나 특정 공간에서 담배 연기를 감지해 알림. 누가 겪는 어떤 문제인지가 분명해서 문제 정의가 쉽습니다.

생각할 점 — 담배 연기인지 다른 냄새인지 센서는 모릅니다. 그래도 "평소와 다른 변화"는 잡을 수 있어요

폐활량 게임 (LED만)

가스 센서 없이도

입김을 세게 불수록 LED가 높이 차오르는 게임. 친구와 점수를 겨룰 수 있습니다. MQ2 대신 입김의 세기(값 변화)를 점수로 씁니다.

한 걸음 더 — 최고 기록을 저장하거나, 3초 안에 몇 칸까지 올리는지 타이머 넣기

환기 알리미

일상의 불편에서

공기가 일정 수준 이상 나빠지면 "창문 여세요"를 LED와 화면으로 알림. 오래 켜두는 장치라 피코의 장점(꾸준함)과 잘 맞습니다.

한 걸음 더 — 며칠 동안 언제 공기가 나빴는지 기록해서 패턴 찾기
엉뚱한 것도 환영

지난 학기엔 "방귀 감지기"가 장난처럼 나왔는데, 알고 보니 실제로 만들 수 있었습니다. 웃긴 아이디어가 오히려 원리를 정확히 건드리는 경우가 많아요. 일단 많이 꺼내세요.

활동 3. 주제 정하고 문제 정의하기

목표 — "누구의 어떤 문제"인지 한 문장으로

아이디어를 하나 골랐다면, 만들기 전에 이 네 칸을 채워 보세요. 화이트보드나 종이에 그림으로 그려도 좋습니다.

# 문제 정의

누가   :  (이 문제를 겪는 사람)
언제   :  (어떤 상황에서)
문제   :  (무엇이 불편한가)

내 장치 :  어떤 데이터를 재서 → 어떻게 알려줄 것인가

예를 들어 이렇게요.

누가: 우리 반 학생들 / 언제: 6교시쯤 / 문제: 공기가 탁한데 아무도 모르고 넘어감 / 내 장치: MQ2로 공기를 재서 → 나빠지면 LED가 빨갛게 차오르고 폰으로 알림
센서가 할 수 없는 일도 적으세요

"MQ2는 연기 종류를 구분 못 한다", "정확한 농도는 모른다" 같은 것들이요. 이걸 아는 게 감점이 아니라 가점입니다. 발표 때 "우리 센서의 한계는 이것이다"를 말할 수 있으면 이해도가 높은 겁니다.

활동 4. 바이브 코딩으로 만들기

목표 — 작게 시작해서 하나씩 더한다

한 번에 다 만들려고 하지 마세요. 지난 학기 학생의 가장 큰 깨달음이 이것이었습니다.

"한 번에 다 하려고 하지 말고 작게 작게 만들어가니까 됐다. 세 번 망해도 네 번째에 되면 그게 완성이다."
1
돌아가는 것부터

5·6차시 코드를 열어 일단 실행되게 만드세요. 빈 화면에서 시작하지 말고, 되는 것 위에 얹습니다.

2
기능 하나씩 AI에게 부탁

"위험할 때 깜빡이게", "폰 화면에 경고 문구", "최고 기록 저장"처럼 한 번에 하나씩. 6차시에 배운 프롬프트 방식대로, 내 환경과 지금 코드를 함께 알려주세요.

3
받은 코드를 내 값에 맞게

AI가 준 숫자는 내 센서 값이 아닙니다. 반드시 내가 잰 값으로 바꾸세요. 지난 학기 학생도 여기서 세 번 실패했습니다.

"AI가 만든 코드를 그대로 쓰지 말고, 내 상황에 맞게 숫자를 바꿔야 한다. 센서마다 평소 값이 다르다."
LED 부탁에는 꼭 이 문장을

6차시에서 배웠죠. AI는 우리가 WS2813을 쓰는지 모릅니다.

WS2813 네오픽셀이라 타이밍을 지정해야 해. 반드시 이렇게 써 줘.
TIMING = (280, 515, 515, 745)
led = NeoPixel(Pin(16), 10, timing=TIMING)
AI와 나눈 대화를 남기세요

무엇을 물었고 어떻게 다시 물었는지가 수행평가 제출물입니다. 대화창을 복사해 둘 곳(구글 문서 등)을 미리 열어두고, 막힐 때마다 붙여넣으세요. 나중에 한꺼번에 모으려면 놓칩니다.

활동 5. 친구에게 보여주고 고치기

목표 — 남의 눈으로 내 것을 본다

어느 정도 됐으면 2명 이상에게 보여주고 의견을 들으세요. 그리고 최소 하나는 반영합니다. 지난 학기 학생의 가장 뿌듯한 순간이 여기서 나왔습니다.

민지: "입김 살짝 불었는데도 빨개진다. 너무 예민함" → 위험 기준을 좀 올렸더니 괜찮아졌다.
"처음엔 내가 만든 거니까 그냥 둘래 싶었는데, 바꿔보니 진짜 더 나아졌다."

숫자 하나 바꾸는 작은 수정이 큰 차이를 만듭니다. 친구 의견을 듣고 반영한 기록은 협력 점수와 직결됩니다.

보여줄 때 물어볼 것

"어때?"보다 구체적으로 물으세요. "이 기준이 너무 예민한 것 같아, 아니면 둔한 것 같아?", "이 색이 위험해 보여?", "설명 없이 봤을 때 뭘 하는 장치인지 알겠어?"

기록하기 — README와 LOG

작년 학생 예시를 참고하세요

깃허브에 두 파일을 씁니다. README.md는 "무엇을 만들었나"(설명서), LOG.md는 "어떻게 만들었나"(과정 일기)예요.

내 프로젝트 링크 공유하기

완성했으면 주소를 제출하세요

깃허브 저장소는 주소(링크) 하나로 통째로 공유됩니다. 파일을 따로 보낼 필요가 없어요.

1
저장소 첫 화면으로 가기

내 저장소 이름을 클릭하면 파일 목록과 README가 보이는 첫 화면이 나옵니다.

2
주소창의 링크를 복사

브라우저 맨 위 주소창을 보면 이런 모양입니다.

https://github.com/내아이디/저장소이름

이 주소를 통째로 복사하세요. 이 링크 하나에 README, LOG, main.py가 다 들어 있습니다.

3
초록색 Code 버튼으로도

주소창이 헷갈리면, 저장소 화면의 초록색 <> Code 버튼을 눌러도 링크가 나옵니다. 거기서 복사해도 됩니다.

4
제출하기

복사한 링크를 띵커벨에 붙여넣어 제출합니다. 친구와 서로 볼 때도 이 링크를 주고받으면 돼요.

Public인지 확인하세요

저장소가 Private이면 나만 볼 수 있어서, 링크를 줘도 친구가 못 엽니다. 저장소 이름 옆에 Public이라고 적혀 있는지 확인하세요. Private이면 Settings 맨 아래에서 바꿀 수 있습니다.

wifi_config.py는 빠졌는지 확인

파일 목록에 wifi_config.py가 안 보여야 정상입니다. 보인다면 우클릭해서 지우거나, 그 파일에서 비밀번호를 지운 뒤 올리세요. 링크는 누구나 열 수 있으니까요.
