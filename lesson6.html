지난 시간 복습

0. 돌아보기 — 5차시 자료
  • LED는 D16, MQ2는 A0. 전원 스위치는 5V
  • LED 코드에는 timing=TIMING이 반드시 들어간다
  • led.write()를 불러야 실제로 켜진다
  • MQ2는 예열이 필요하고, 평소 값은 센서마다 다르다
시작 전 확인

부품을 연결하고 MQ2를 먼저 꽂아 두세요. 오늘 앞부분을 하는 동안 예열이 끝납니다.

그리고 지난 시간에 적어둔 내 센서의 평소 값을 꺼내 두세요. 집에서 하는 거라면 교실과 다를 수 있으니 다시 확인해도 좋습니다.

TIMING, 왜 필요할까

1. 돌아보기 — 지난 시간에 그냥 넘어간 한 줄

5차시에 이 줄을 이유 없이 붙이라고 했습니다. 오늘은 그 이유를 봅니다. AI에게 부탁할 때 이걸 설명할 수 있어야 하거든요.

TIMING = (280, 515, 515, 745)
led = NeoPixel(Pin(16), 10, timing=TIMING)

데이터선이 딱 한 가닥입니다

네오픽셀 LED에는 신호선이 하나뿐입니다. 보통 데이터를 보낼 때는 "지금 읽어라"를 알려주는 클럭선이 따로 있는데, 이 LED에는 그게 없어요.

그러면 0과 1을 어떻게 구분할까요? 답은 신호가 켜져 있는 시간의 길이입니다.

  • 짧게 켜고 → 길게 끔 = 0
  • 길게 켜고 → 짧게 끔 = 1

이 "짧게·길게"의 정확한 길이가 칩마다 조금씩 다릅니다. 단위는 나노초(ns, 10억분의 1초)이고, 네 개의 값으로 정합니다.

TIMING = (280, 515, 515, 745)
#          T0H  T0L  T1H  T1L
#           │    │    │    └── "1" 신호의 꺼짐 시간 (ns)
#           │    │    └─────── "1" 신호의 켜짐 시간 (ns)
#           │    └──────────── "0" 신호의 꺼짐 시간 (ns)
#           └───────────────── "0" 신호의 켜짐 시간 (ns)

마이크로파이썬의 NeoPixel 기본값은 원조 WS2812용입니다. 우리가 쓰는 WS2813 Mini에 그대로 적용하면 신호를 0인지 1인지 잘못 읽어요. 그래서 색이 깨지거나 아예 안 켜집니다.

(280, 515, 515, 745)는 WS2813 Mini 데이터시트 규격 안에 들어가는 안전한 값입니다.

비유하면

이 LED 부품에 맞는 모스 부호 속도입니다. 짧은 신호와 긴 신호로 메시지를 보내는데, 속도가 안 맞으면 상대가 못 알아듣는 것과 같아요.

막힐 때 1순위

LED가 이상하게 깜빡이거나, 요청한 색과 다른 색이 나오거나, 아예 안 켜진다면 TIMING을 빠뜨렸는지부터 확인하세요. 오늘 AI가 준 코드가 안 돌아가는 원인의 대부분이 이겁니다.

코드
안 됨led = NeoPixel(Pin(16), 10)
됨led = NeoPixel(Pin(16), 10, timing=TIMING)

AI는 우리가 어떤 LED를 쓰는지 모릅니다. 그래서 위쪽 코드를 줍니다. 아래쪽으로 고치는 건 우리 몫이에요. 뒤에서 AI에게 부탁할 때 이걸 미리 알려주는 법을 배웁니다.

직접 타이핑활동 1. 전압과 %로 바꾸기

목표 — 같은 값을 여러 방식으로 표현한다

read_u16()이 주는 0~65535라는 숫자는 사실 전압을 눈금으로 나눈 것입니다. 0이 0V, 65535가 3.3V예요. 그러면 지금 값이 몇 V인지 계산할 수 있겠죠.

from machine import ADC, Pin
import time

gas = ADC(Pin(26))

while True:
    value = gas.read_u16()

    voltage = value / 65535 * 3.3      # 전압으로
    percent = value / 65535 * 100      # 백분율로

    print(value, "|", round(voltage, 2), "V |", round(percent, 1), "%")
    time.sleep(0.5)

맨 위 슬라이더를 움직여 보면 세 숫자가 어떻게 연결되는지 보입니다. 값 하나가 바뀐 게 아니라, 표현 방법이 세 가지인 것입니다.

2차시와 같은 계산입니다

온도 센서에서 volt = raw * 3.3 / 65535를 썼던 것 기억나나요? 똑같습니다. 아날로그 센서는 전부 이 방식이에요. 다만 온도 센서는 그 뒤에 온도로 바꾸는 공식이 하나 더 있었고, MQ2는 ppm으로 바꾸는 정확한 공식이 없습니다.

MQ2를 정확한 농도로 바꾸려면 저항비 계산과 보정이 필요한데, 그건 이 수업 범위를 넘습니다. 그래서 우리는 상대적인 변화만 봅니다. "평소보다 얼마나 올랐나"로요.

직접 타이핑활동 2. 평균 내서 안정시키기

목표 — 흔들리는 값을 다루기 쉽게 만든다

값이 계속 튀어서 그래프가 지저분해집니다. 2차시 온도 센서에서 썼던 방법을 그대로 쓰면 돼요.

def read_average(count=10):
    """여러 번 재서 평균 내기"""
    total = 0
    for _ in range(count):
        total += gas.read_u16()
        time.sleep_ms(10)
    return total // count


while True:
    print(read_average())
    time.sleep(0.5)

time.sleep_ms(10)은 10밀리초, 즉 0.01초입니다. 10번 재는 데 0.1초가 걸려요.

실험해 보기

count를 3, 10, 50으로 바꿔가며 비교해 보세요. 많이 잴수록 안정되지만 그만큼 느려집니다. 어디가 적당한지는 만드는 사람이 정합니다.

직접 타이핑활동 3. 그래프로 보기

목표 — 숫자 대신 모양으로 데이터를 본다

토니에는 플로터라는 기능이 숨어 있습니다. print()로 숫자만 찍으면 자동으로 그래프를 그려줘요.

1
플로터 켜기

토니 메뉴에서 보기(View) → 플로터(Plotter)를 클릭합니다. 셸 옆에 빈 그래프 창이 생깁니다.

2
숫자만 찍는 코드 실행

글자를 섞으면 그래프가 안 그려집니다. 숫자 하나만 출력하세요.

while True:
    print(gas.read_u16())
    time.sleep(0.1)
3
입김 불어보기

선이 위로 솟았다가 천천히 내려옵니다. 올라가는 속도와 내려오는 속도가 다르다는 걸 숫자로 볼 때보다 훨씬 선명하게 알 수 있어요.

코드는 거의 그대로인데 왜 달라 보일까

활동 2의 코드와 거의 같습니다. 그래프를 그린 건 토니라는 도구예요. 같은 데이터라도 어떻게 보여주느냐에 따라 발견하는 게 달라집니다. 이게 데이터 시각화가 필요한 이유입니다.

바이브 코딩여기부터는 AI에게 부탁합니다

목표 — 잘 물어보는 법을 익힌다

지금까지는 한 줄씩 직접 쳤습니다. 이제부터 만들 것은 100줄이 넘어요. 직접 치는 대신 원하는 걸 말로 설명해서 만듭니다. 이걸 바이브 코딩이라고 합니다.

좋은 부탁의 조건

AI는 여러분의 화면도, 어떤 부품을 쓰는지도, 지금 코드가 어떤 모양인지도 보지 못합니다. 우리가 알려준 것만 알아요. 그래서 이 네 가지를 꼭 넣어야 합니다.

넣을 것예시
내 환경라즈베리파이 피코 2 W, 마이크로파이썬
지금 상태MQ2가 GP26에 연결됨, read_u16()으로 값을 읽는 중
원하는 것폰 브라우저에서 실시간 그래프로 보고 싶다
조건·제약외부 라이브러리 없이, wifi_config.py에서 불러오기
특히 중요한 것 — 부품의 특별한 사정

앞에서 본 것처럼 우리 LED는 timing=TIMING이 없으면 작동하지 않습니다. AI는 이걸 모르기 때문에, 말해주지 않으면 매번 작동하지 않는 코드를 줍니다.

그래서 LED가 들어가는 부탁에는 이 문장을 꼭 붙이세요.

WS2813 네오픽셀이라 타이밍을 지정해야 해. 반드시 이렇게 써 줘.
TIMING = (280, 515, 515, 745)
led = NeoPixel(Pin(16), 10, timing=TIMING)

이런 걸 내가 아는 것을 AI에게 알려주는 일이라고 합니다. AI가 나보다 많이 아는 것 같아도, 내 책상 위 물건은 내가 더 잘 압니다.

바이브 코딩활동 4. 폰에서 실시간 그래프 보기

목표 — 원하는 걸 설명해서 대시보드를 만든다

4차시에 만든 웹 화면은 5초마다 페이지 전체를 새로 불러왔습니다. 이번엔 다릅니다. 화면은 그대로 두고 숫자만 받아와 그래프에 이어 붙여요. 훨씬 부드럽습니다.

AI에게 이렇게 부탁해 보세요
라즈베리파이 피코 2 W에서 마이크로파이썬을 쓰고 있어.
MQ-2 가스 센서가 GP26(ADC0)에 연결되어 있고,
read_u16() 으로 0~65535 값을 읽고 있어.

이걸 Wi-Fi 웹서버로 띄워서, 폰 브라우저에서 http://피코IP 로
접속하면 실시간 그래프가 보이게 만들어 줘.

조건:
- HTML은 별도 파일 없이 파이썬 코드 안에 넣어 줘
- 0.5초마다 새 데이터로 업데이트
- 그래프는 Chart.js 를 CDN에서 불러와서 써 줘
- Wi-Fi 정보는 wifi_config.py 에서 가져와 줘
  (WIFI_SSID, WIFI_PASSWORD)
- /data 경로로 요청하면 JSON 으로 값만 주고,
  그 외 경로는 HTML 페이지를 주는 구조로 해 줘
- 한글 주석 친절하게

받은 코드를 읽어보기

실행해서 되는 걸 확인했으면, 그냥 넘어가지 말고 세 가지만 찾아보세요.

  • 센서 값을 읽는 줄은 어디인가
  • /data 요청과 그 외 요청은 어떻게 다르게 처리하나
  • 브라우저는 몇 초마다 새 값을 요청하나 (힌트: setInterval)

모르는 줄이 있으면 AI에게 "이 줄이 무슨 일을 하는 거야?"라고 다시 물으세요. 코드를 받는 것보다 이게 더 중요합니다.

JSON이 뭔가요

프로그램끼리 데이터를 주고받을 때 쓰는 약속된 형식입니다. {"value": 32418}처럼 생겼어요. 사람이 봐도 읽히고 컴퓨터도 바로 이해합니다.

앞으로 AI API를 쓸 때도 이 형식으로 대화하게 됩니다. 오늘 눈에 익혀 두세요.

그래프가 안 보인다면

Chart.js를 인터넷에서 불러오기 때문에, 폰이 인터넷에 연결되어 있어야 그래프가 그려집니다. 숫자는 보이는데 그래프만 비어 있다면 이것부터 확인하세요.

바이브 코딩활동 5. 상태 판정 붙이기

목표 — 숫자를 사람의 말로 바꾼다

32418이라는 숫자를 보고 좋은 건지 나쁜 건지 알 수 있나요? 못 알아봅니다. 판정해서 알려줘야 쓸모가 생겨요.

AI에게 이렇게 부탁해 보세요
방금 만든 대시보드에 정보 카드 4개와 상태 판정을 추가해 줘.

카드 4개:
1. ADC 원본값
2. 전압 (V)
3. 비율 (%)
4. 상태

상태 판정 기준:
- 값 < (내가 정한 숫자)  → 좋음 (초록)
- 값 < (내가 정한 숫자)  → 주의 (노랑)
- 그 이상               → 위험 (빨강)

추가로:
- 상태에 따라 숫자 색과 그래프 선 색도 같이 바뀌게 해 줘
- 화면이 좁으면 카드가 자동으로 줄바꿈되게 해 줘
괄호 안의 숫자는 여러분이 채웁니다

AI에게 "적당한 기준으로 해 줘"라고 하면 그럴듯한 숫자를 지어냅니다. 그런데 AI는 내 센서를 본 적이 없어요.

지난 시간에 잰 평소 값을 기준으로 직접 정하세요. 예를 들어 평소가 15000이라면 주의는 18000쯤, 위험은 25000쯤으로 잡고 입김을 불어 확인해 보는 식입니다.

기준이 맞는지는 써 보면 압니다. 평소에 계속 빨강이면 너무 낮은 거고, 아무리 불어도 초록이면 너무 높은 겁니다.

한 걸음 더

여유가 있으면 디자인도 바꿔 보세요. AI에게 이렇게 말하면 됩니다.

  • "다크 테마로 바꿔 줘. 어두운 남색 배경에 둥근 카드"
  • "제목을 크게 하고 글자 사이를 넓혀 줘"
  • "측정 중이라는 표시로 깜빡이는 점을 넣어 줘"

"예쁘게 만들어 줘"보다 구체적으로 말할수록 원하는 결과가 나옵니다.

바이브 코딩활동 6. LED까지 연결하기

목표 — 화면과 실물이 함께 반응하게 한다

폰 화면은 봐야 보입니다. LED는 지나가다 눈에 띄죠. 둘을 같이 쓰면 훨씬 쓸모 있습니다.

AI에게 이렇게 부탁해 보세요
지금 코드에 네오픽셀 LED 표시를 추가해 줘.

⚠️ 중요: WS2813 네오픽셀이라 타이밍을 지정해야 해.
반드시 이렇게 써 줘.
TIMING = (280, 515, 515, 745)
led = NeoPixel(Pin(16), 10, timing=TIMING)
(LED 개수는 내 부품에 맞게 바꿀 거야)

동작:
- 센서 값에 따라 LED가 막대그래프처럼 차오르게
- 좋음이면 초록, 주의면 노랑, 위험이면 빨강
- 위험할 때는 깜빡이게
- 밝기는 눈부시지 않게 낮춰 줘

그리고 웹 화면에 접속할 때만 LED가 갱신되지 않고,
접속이 없어도 계속 움직이게 하려면 어떻게 해야 하는지 알려 줘.
마지막 질문이 핵심입니다

웹서버는 누가 접속할 때까지 멈춰서 기다립니다. 그래서 그냥 합치면 폰으로 접속할 때만 LED가 바뀌어요.

해결 방법이 몇 가지 있는데, AI에게 물어보고 어떤 방법을 쓸지는 여러분이 정하세요. 설명이 이해되지 않으면 "더 쉽게 설명해 줘"라고 다시 물으면 됩니다.

점검하기

ADC 값 32768은 몇 V인가요?
약 1.65V입니다. 65535가 3.3V이므로 절반인 32768은 3.3V의 절반이 됩니다.
MQ2 값을 정확한 ppm으로 바꿀 수 없는 이유는?
정확한 농도를 구하려면 저항비 계산과 기체별 보정이 필요합니다. 또 어떤 기체인지 구분하지 못하므로, 우리는 절대 농도가 아니라 상대적인 변화만 봅니다.
AI에게 부탁할 때 꼭 넣어야 할 네 가지는?
내 환경(보드·언어), 지금 상태(핀 번호·현재 코드), 원하는 것, 조건과 제약입니다. AI는 내 화면을 보지 못하기 때문입니다.
LED 관련 부탁에 TIMING을 꼭 적어야 하는 이유는?
AI는 우리가 WS2813을 쓰는지 모릅니다. 알려주지 않으면 기본 타이밍으로 코드를 만들고, 그러면 LED가 작동하지 않습니다.
판정 기준 숫자를 AI에게 맡기면 안 되는 이유는?
AI는 내 센서를 측정한 적이 없습니다. 센서마다 평소 값이 다르므로 기준은 내가 잰 값으로 직접 정해야 합니다.
